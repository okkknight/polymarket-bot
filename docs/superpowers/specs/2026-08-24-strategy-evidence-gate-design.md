# 策略证据筛查与准入门设计

## 目标

在不发送真实订单、不改动仓位与资金风控参数的前提下，建立可复现的市场数据采集、成本回放和策略准入链路。新的候选策略只在外部 BTC 市场对 Polymarket 存在已验证的领先性，且模型公平概率相对真实可成交价存在成本后偏离时交易；证据不足或失败时必须保持 `NO_GO`。TWAP 窗口从每个市场的实际规则中解析，绝不硬编码。

## 非目标

- 不自动开启实盘，不改变现有显式实盘批准开关。
- 不改变下单额度、仓位上限、订单状态机、资金与恢复语义。
- 不承诺或宣称策略盈利。
- 不把任何历史或论文结果视为当前 5 分钟市场的盈利证明。
- 不复用现有 shadow 的模拟成交结果作为放行证据。

## 现状与问题

`ops/scripts/run_shadow_with_proxy.sh` 将可选的 `OUT_PREFIX` 直接映射到 `data/` 下的固定文件。一次被调度器重启的运行会覆盖同名 CSV/JSONL。`src/runners/polymarket_paper_trading_realtime.mjs` 只以 BTC 的短线涨跌生成方向，使用 CLOB midpoint 和固定滑点模拟成交；它没有估计合约概率，缺少真实 bid/ask、挂单量、数据覆盖率与时间切分，因此不能证明 live 策略的成本后期望值。

## 方案选择

采用独立的只读策略筛查器，但复用既有外部 BTC 数据和回放模块，而不扩展 shadow runner 或并行复制策略框架。

- 采集器与交易运行器隔离：不导入 execution、ledger 或 live gateway，不读取本地交易状态，也不读取 API 凭据。
- 采集器从公开 Gamma/CLOB/Polymarket RTDS Chainlink/OKX 接口取得候选 5 分钟市场、YES/NO 最优盘口、市场费率、原始 Chainlink BTC/USD 报告、BTC 现货和永续行情/盘口。
- 回放器只读取已完成采集目录，不访问网络；先验证外部市场对 Polymarket 的领先性，再以校准的公平概率选择方向，并以真实 ask 买入、真实 bid 卖出和逐笔协议费用计算保守净收益。
- 策略准入由一份已验证报告提供；缺失、过期或非合格报告时 live 路径不生成交易意图。

现有 `src/runners/polymarket_paper_trading_realtime.mjs` 已从 OKX `BTC-USDT` ticker 获取外部价格；`src/tools/polymarket_external_lead_dataset.mjs` 已将 OKX 1 秒历史蜡烛与 Polymarket 快照对齐并产出 1/2/3/4/5/10 秒 BTC 收益率；`src/tools/polymarket_replay_paper.mjs` 已有 `external_price_lead` 候选。它们保留为输入与基准候选，而不是重写。

## 组件与接口

### 1. 策略筛查采集器

新增 `src/tools/polymarket_strategy_screen_collector.mjs` 和 `ops/scripts/run_strategy_screen.sh`。

运行器生成格式为 `YYYYMMDDTHHMMSSZ-<随机后缀>` 的 run ID，并创建：

```
runs/strategy-screen/<run-id>/
  manifest.json
  raw.jsonl
  report.json
```

目录必须不存在；若已存在立即失败。`raw.jsonl` 只追加，包含采集时间、市场/到期时间、市场规则声明的 TWAP 窗口、原始 Chainlink 报告及由其计算的结算基准/起点值、YES 与 NO token、最优 bid/ask、对应挂单量、市场 fee schedule、BTC 现货与永续价格、两侧盘口不平衡、近期 BTC 价格窗口、每个请求的时间与错误标识。所有原始字段保留，不用 `0` 或空市场价格替代失败请求。

`manifest.json` 在开始时记录 schema 版本、run ID、开始时间、预期时长与只读声明；结束时记录结束时间、退出原因、有效行数、失效行数和 `raw.jsonl` 的 SHA-256。无论正常结束或受控异常都写入终态 manifest；已存在的 raw 数据不可重写。

采集器按 `--durationSec` 自行退出。它不创建 launchd/at 任务；若需要后台运行，外部执行器也必须每次传入新的 run ID。重复启动不能覆盖原始资料。

### 2. 数据校验与成本回放

新增 `src/tools/polymarket_strategy_screen_report.mjs` 及可测试的纯函数模块。

报告器验证 manifest 哈希、单调时间、有效行比例、连续缺口、盘口完整性和市场到期信息。无法验证的 run 返回 `DATA_INSUFFICIENT`，保留原因列表，不计算收益或将缺失误判为无交易机会。

回放使用按时间排序的原始快照，并且预注册三类候选：无交易基准、仅由起点价/现价/剩余时间/历史波动率形成的概率基准、以及加入外部现货/永续短窗收益和盘口不平衡的领先性模型。领先性模型必须先在训练日中显示外部特征对随后 Polymarket 概率变化或最终结算标签有稳定增量信息；否则该模型不合格，不产生交易。

合格候选只使用当时已经可见的特征，以市场规则声明窗口下 Chainlink TWAP 的合约起点值、当前 TWAP、剩余结算时间和短周期波动率估计 YES 公平概率；NO 概率为其补数。OKX 现货/永续只作为解释并预测随后 TWAP/Polymarket 变化的领先特征，不能替代结算基准。它只能在 `fair_probability - entry_ask >= total_cost + edge_buffer` 时买入对应 outcome。`total_cost` 包括进入 ask、退出 bid 所体现的盘口成本，以及按市场实际 fee schedule 逐笔计算的 `shares × rate × price × (1-price)` taker fee。不存在可交易盘口、可解析规则窗口、Chainlink 起点/当前 TWAP、费用参数、波动率或已验证领先性时不制造成交。数据按日切分为训练和逐日样本外验证段，禁止循环、泄漏未来价格或交叉复用同一时段。

### 3. 准入报告与交易防火墙

报告包含：run ID、输入哈希、数据质量、成本后交易统计、时间分片统计、结论、结论原因和生成时间。结论严格为：

- `DATA_INSUFFICIENT`：完整性、覆盖率、时长或结果标签不足；不能放行。
- `SCREEN_FAIL`：完整数据下，样本外净收益非正、交易数不足或任一必需时间分片为负；不能放行。
- `ELIGIBLE_FOR_REVIEW`：质量和全部预设统计门槛均通过；仅表示可由人类复核，不等同可实盘。

在 live runner 建立任何交易 intent 前，加载显式指定的报告。报告必须为 `ELIGIBLE_FOR_REVIEW`、哈希有效且未过期；否则产生可诊断的阻止事件并不下单。现有 `LIVE_DRY_RUN`、人工批准与风险控制仍是后续独立门槛。

候选规则还必须在每一笔意图前检查：市场规则标明 Chainlink 60 秒 TWAP、同一合约的起点与当前 TWAP 都已采集且时间新鲜、距离结算至少 60 秒、盘口两侧完整、目标 outcome 的 ask 不高于模型公平概率扣除成本缓冲，并且盘口挂单量足以覆盖最小订单。任何条件不满足均为无交易，而非反向信号。

## 默认筛查阈值

报告把下列值写入自身，防止日后无法解释结论：

- 半小时采集仅用于验证数据管道，不产生策略资格结论。当前部署的 7 天 VPS 筛查同样只用于数据管道和早期淘汰：报告只能为 `DATA_INSUFFICIENT` 或 `SCREEN_FAIL`，绝不能产生策略资格结论。
- 策略资格要求连续至少 14 个自然日、1 秒采样，覆盖约 4,000 个完整的 5 分钟合约，且至少 95% 有效快照。
- 任意连续数据缺口不超过 10 秒；超过即 `DATA_INSUFFICIENT`。
- 前 7 个完整自然日仅用于锁定特征、模型与阈值；后 7 个完整自然日仅用于逐日样本外评估。
- 每个样本外日必须至少有 10 笔可成交的模拟完整交易；总样本外至少覆盖 100 笔交易和 100 个结束合约。
- 每个样本外日、以及总体样本外，成本后净收益都必须为正；外部领先性必须在训练日和样本外日都成立。

这些是研究筛查门槛，不是仓位或风险参数。结果只允许人工复核，默认不会触发真实交易。

## 错误处理与可观测性

- 网络/解析失败写入带错误码的原始记录；关键字段缺失的记录计为失效。
- 采集期间市场轮换会记录市场切换，而不是把不同市场拼成同一无标识序列。
- 写入、哈希或 JSON 解析失败使报告 `DATA_INSUFFICIENT` 并以非零退出；不会删除已采数据。
- 所有命令只输出 run ID、路径、计数和状态，绝不打印凭据或交易账户数据。

## 测试与验收

Node 测试必须覆盖：

1. run ID/目录冲突被拒绝，旧 `raw.jsonl` 不变。
2. 完整行情写入有效快照，缺失 bid/ask 或 BTC 价格记为失效而非零值。
3. 哈希、时间倒退、连续缺口和覆盖率失败均输出 `DATA_INSUFFICIENT`。
4. 回放以 ask 开仓、bid 平仓并扣费；midpoint 有利但真实 spread 后为负的样例必须失败。
5. 开发/样本外时间切分不重叠，不能通过重复同一段数据增加交易数。
6. 没有合格、完整且未过期报告时，live 路径不创建 intent；合格报告也不绕过既有 live 批准门。

完成后执行聚焦 Node 测试、现有执行/恢复安全测试、`node --check`、`bash -n` 和 `git diff --check`。若 `npm test`、lint 或 build 脚本不存在，报告中明确说明。

## 风险与限制

半小时筛查只足以发现明显的数据或成本问题，不能证明策略优势。即使满足连续 14 日样本要求，`ELIGIBLE_FOR_REVIEW` 也不是实盘批准；真实交易仍需要人类的单独授权和现有风险检查。外部领先性可能消失，概率模型也不能保证盈利。任何后续调整仓位、风险参数、市场范围或自动实盘开关，都需要单独批准。

## 研究依据与策略选择

Crypto taker fee 随成交价格变化，maker 不收协议 taker fee，因此研究工具必须读取实际费用参数并在每笔模拟中精确扣费。公开 CLOB 数据提供 outcome token、订单簿和市场费用字段。外部 BTC 现货/永续市场可能承担更强的价格发现功能，但这种关系具有场所与时段依赖性；本系统把它作为待证伪假设。

不采用无对冲做市：它需要可靠的排队位置、库存管理、撤单速度与足够资本，当前小额账户不具备这些条件。也不把长到期 BTC 阈值合约与期权之间的研究价差外推到 5 分钟合约。唯一候选是成本后、样本外、逐日验证通过的外部领先性概率模型；任何未通过候选保持无交易。

现有外部价格链路不能直接放行：live runner 仅以 1 秒与 3 秒收益穿越固定阈值决定方向，并以 OKX 价作为隐含结算基准；历史数据工具以 `abs(1-(yes+no))` 作为 spread 代理而非真实订单簿；回放按价格标记、固定费率/滑点计算，并未采集 Chainlink TWAP、检验领先性或按自然日做样本外切分；快速回放还循环复用同一组行。因此本任务只补齐这些缺口，并把旧的动量候选降为不可部署的对照组。
